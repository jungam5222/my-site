## 개요

고려대 인공지능 학회 **AIKU**와 한양대 **HAI**가 함께 연 **HAIKUTHON 2026**에 4인 팀으로 참가했어요. 2026년 11월 21일 오후부터 22일 아침까지 고려대 애기능생활관에서 무박 2일로 진행됐어요.

저는 **2단계 재정렬기**를 맡았어요. 1단계가 뽑은 후보 20장을 다시 줄 세우는 BLIP 모델을 "가족 안에서 1등 고르기" 문제로 학습시켰고, 이 파이프라인이 Public **0.4091**을 냈어요.

## 문제 정의

**Multimodal RAG**: 영문 설명(query)이 주어지면 후보 이미지 중에서 설명에 맞는 이미지를 찾아 상위 5장을 순서대로 내는 문제예요. 정답 이미지는 문장마다 한 장이에요.

> "Resting on one bench, purple in color, is one backpack that is open and blue."
> 보라색 벤치 위에 파란 배낭 하나가 열린 채 놓여 있어요.

- **데이터**: 운영진이 직접 만든 AI 생성 이미지. Train은 텍스트–이미지 4,000쌍, Test는 문장 8,000개와 이미지 16,000장이에요.
- **점수**: 문장마다 (Recall@1 + NDCG@5) / 2. 정답이 1위면 1점, 2위 0.315, 3위 0.25, 4위 0.215, 5위 0.193, 5위 밖이면 0점이에요.
- **제약**: 예측이 아니라 모델을 제출해요. NVIDIA L4(24GB) 한 장에서 추론 **15분 이내**, ZIP 5GB 이하, 팀당 25번까지 낼 수 있어요.
- 최종 순위는 리더보드 70% + 결선 발표 30%예요.

## 데이터에서 찾은 것: "가족"

팀원이 학습 데이터를 분석해 보니, 문장 4,000개가 **같은 장면에서 색·좌우·개수만 바꾼 4장·8장짜리 가족**으로 묶여 있었어요(97.7%가 가족에 속함). 베이스라인의 1등 오답 중 **91.5%가 같은 가족 이미지**였어요. 즉 가족은 잘 찾는데, 가족 안의 순서를 못 정하는 문제였어요.

그래서 팀은 **1단계로 후보를 넓게 뽑고, 2단계에서 가족 안의 미세한 차이를 가리는** 두 단계 구조로 갔어요.

## 제가 한 것

### 1. VQAScore로 재정렬해 보기 (중단)

VLM(Qwen3-VL-2B)에 "이 그림이 이 문장을 보여주나요?"라고 묻고 "Yes" 확률을 점수로 써 봤어요.

| 지표 | 값 |
| --- | ---: |
| 정답 쌍을 "Yes"로 판단 | 97.5% |
| 가족 8장 중 자기 이미지 1등 | 17.6% (무작위 12.5%) |

정답에는 거의 다 Yes라고 하지만, 색·좌우만 다른 형제 이미지에도 똑같이 Yes라고 해서 재정렬기로는 쓸 수 없었어요.

### 2. 가족 listwise로 학습한 BLIP 재정렬기 (메인)

- **1단계**가 문장마다 후보 20장을 뽑으면, **BLIP ITM**이 그 20장의 순서를 다시 매겨요.
- BLIP을 **가족 안에서 1등 고르기**로 학습했어요.
  - 텍스트→이미지: 문장 1개 vs [정답 + 형제 이미지 최대 7장 + hard negative]
  - 이미지→텍스트: 이미지 1장 vs [정답 문장 + 형제 문장 + 색 바꾸기, left↔right, above↔below로 만든 가짜 문장]
  - listwise softmax cross-entropy. BLIP ViT는 고정하고 이미지 특징을 캐시해서 Colab T4에서도 돌아가게 했어요.
- 검증은 **가족 단위로** 나눴어요. 형제가 학습과 검증 양쪽에 섞이면 점수가 부풀기 때문이에요.
- 최종 점수는 `z(BLIP ITM) + 0.25 · z(1단계 코사인)`이에요. z는 문장마다 후보 20장 안에서 표준화한 값이에요.
- 학습 전 검증 0.545 → 가족 listwise 1 epoch 후 **0.754**.

### 3. 1단계를 FG-CLIP2로

팀원이 찾은 **FG-CLIP2 Large**로 1단계를 바꿨어요. 모델 코드를 제출 ZIP 안에 넣어서 서버에서 인터넷 없이 돌아가게 했어요. 15분 중 **11분 47초**를 써서 Public 0.4091이 나왔어요.

### 4. 더 어려운 오답으로 다시 학습 (효과 없음)

가족을 FG-CLIP2 임베딩으로 다시 묶고, **개수 바꿔치기**("two cacti + one tape measure" ↔ "one cactus + two tape measures")나 물체 역할 교환 같은 가짜 문장, **좌우반전 이미지**를 더해 BLIP을 다시 학습했어요. 좌우반전은 문장의 left↔right도 같이 바꿀 때만 정답으로 쓰고, 이미지만 뒤집으면 오답으로 썼어요. 검증은 0.7638로 올랐지만 Public은 0.4037로 조금 내려갔어요.

### 5. 병목 찾기: 1단계 비교

검증(후보 4,000장)에서는 정답이 거의 항상 top-10에 들어오는데, Test는 후보가 16,000장이라 Public R@5가 0.70에 그쳤어요. 1단계를 SigLIP so400m으로 바꿔 비교해 봤지만 FG-CLIP2가 정확도(0.4957 vs 0.4436)와 속도(약 222초 vs 326초) 모두 나아서 유지했어요.

## 결과

| 제출 | Public | L4 추론 시간 |
| --- | ---: | ---: |
| 스타터 SigLIP 단독 | 0.2319 | 8분 59초 |
| FG-CLIP2 단독 | 0.3149 | 3분 42초 |
| **FG-CLIP2 top-20 + 가족 BLIP 재정렬** | **0.4091** | 11분 47초 |
| 위 + 새 네거티브·좌우반전으로 재학습한 BLIP | 0.4037 | |

FG-CLIP2 단독보다 **+0.094** 올랐어요. 0.4091 제출의 세부 점수는 R@1 0.3053, R@5 0.7037, NDCG@5 0.5129예요.

## 배운 점

> 검증 점수가 0.76이어도 Public은 0.41이었어요. 검증 후보가 4,000장이고 Test 후보가 16,000장이라, **검증을 Test와 같은 크기로 만들지 않으면** 어디가 병목인지 늦게 알게 돼요.

- 2단계를 아무리 다듬어도, 정답이 1단계 후보 안에 없으면 소용없어요. 마지막에는 1단계 recall이 병목이었어요.
- 15분 제한 안에서는 K(후보 수)를 늘리는 것과 재정렬 모델의 무게가 서로 맞바꾸는 관계였어요. K=50이 검증에서 조금 더 좋았지만 시간 때문에 K=20을 유지했어요.
- VQAScore처럼 "맞다/아니다"만 묻는 방식은 미세한 차이를 못 가려요. 비교 대상을 같이 놓고 **그중 1등을 고르게** 학습하는 게 훨씬 잘 맞았어요.
